# 2. LLM 技術原理與防幻覺架構

## 一、大語言模型（LLM）驅動虛擬病人的運作原理
大語言模型（Large Language Model, LLM）透過海量醫學文獻、臨床語料與對話資料集之預訓練，具備深度語義解析與情境對話生成能力 [REF-01, p.2; REF-02, p.2; REF-06, p.2]。在虛擬病人系統中，LLM 的實作技術架構已由早期簡單的單一提示詞，演進為多層次的複雜系統 [REF-06, p.4]：

```
[LLM 虛擬病人六大技術實作架構分類 (Jo et al., 2025)]
1. 臨床劇本自動生成 (Scenario Generation, 20%)：利用多階段反饋或 Agentic 工作流快速產製教案
2. 基礎提示詞驅動 VP (Simple Prompt-Based, 22%)：僅憑單一角色提示詞驅動，成本低但幻覺率偏高
3. 迭代回饋與自動評分 (Feedback & Scoring, 20%)：整合客觀量規 (MIRS/3E) 即時評估學生表現
4. 擬真度與自適應系統 (Realism & Adaptability, 15%)：多模態化身與 Adaptive-VP 閉環行為動態調適
5. 知識驅動多智慧體混合 (Knowledge Multi-Agent, 10%)：串接知識圖譜 (KG)、RAG 與多 Agent 協同演化
6. 心理健康專業系統 (Mental Health Oriented, 13%)：注入 CBT/MI 理論模型，模擬抗拒與情緒波動
```

## 二、臨床模擬的核心技術威脅與偏誤型態
在將 LLM 應用於護理教育時，系統面臨三大主要技術威脅與一項關鍵心理偏誤 [REF-01, p.2, p.5; REF-04, p.9–10; REF-06, p.2]：
1. **臨床腳本不一致之幻覺（Script-Inconsistent Hallucinations）**：模型自行虛構合乎語言邏輯但臨床醫學錯誤、或與核定案例劇本矛盾的症狀、發病時程、用藥史或過敏史 [REF-01, p.6, p.8; REF-04, p.9; REF-06, p.7]。在基礎提示詞驅動的系統中，劇本外幻覺發生率常高達 56.4% [REF-06, p.7]。
2. **角色漂移（Role Drift / Role Switching）**：AI 忘記自己「正在扮演病人」，反客為主以護理師、主治醫師或通用 AI 助手的口吻向學生提供衛教或診斷建議 [REF-01, p.5, p.8; REF-06, p.7]。
3. **隱藏臨床中繼資料洩露（Protected Metadata Leakage）**：學生若直接詢問「你有什麼病？」或「你的檢傷是第幾級？」，未經約束的模型可能會直接吐出後台劇本標註的臨床診斷（Diagnosis）或檢傷級別（Triage category）[REF-01, p.4, p.8]。
4. **AI 過度迎合偏誤（AI Accommodation Bias）**：LLM 內建之對齊機制傾向友善與合作，容易模擬出過度溫和、百依百順且有問必答的「過度理想化病患」，導致護理學生無法練習應對真實臨床中常見的焦慮、模糊、甚至敵對不合作態度 [REF-04, p.7, p.10; REF-06, p.14]。

## 三、分層防幻覺架構（Layered Hallucination Mitigation Architecture）
依據 Chan 等人（2026）在護理檢傷模擬系統（AI Triage）中的實證工程設計，單靠基礎提示詞無法有效抑制臨床幻覺，必須建構一套**「分層防幻覺控制架構」** [REF-01, p.1, p.5]：

```
┌────────────────────────────────────────────────────────┐
│ 1. 接地提示詞 (Case-Grounded Prompting)                │
│    納入臨床專家審定之案例劇本（症狀、病史、時程、生活史） │
├────────────────────────────────────────────────────────┤
│ 2. 少樣本範例對話 (Few-Shot Conversational Exemplars) │
│    每情境提供 2–3 組示範問答，錨定語氣、風格與回應界線 │
├────────────────────────────────────────────────────────┤
│ 3. 明確負向角色約束 (Explicit Negative Constraints)     │
│    嚴禁脫離病人角色、嚴禁直接透露診斷/檢傷等級/處置計畫 │
├────────────────────────────────────────────────────────┤
│ 4. 工作階段歷程管理 (Session-Level Memory Handling)    │
│    單次對話維護連貫上下文，工作階段結束即刻清除快取    │
├────────────────────────────────────────────────────────┤
│ 5. 生成參數精密校準 (Calibrated Generation Settings)   │
│    溫度降至 0.3；Max tokens 設為 4000；懲罰值設為 0    │
├────────────────────────────────────────────────────────┤
│ 6. 雲端安全過濾器閥值調校 (Safety-Filter Calibration)   │
│    避免非英語系正當臨床問診（如求醫原因）遭誤判阻斷   │
└────────────────────────────────────────────────────────┘
```

### 具體實作細節與參數設定：
- **接地提示詞（Case-Grounded Prompting）**：將經臨床專家與醫院管理局（Hospital Authority）護理主管雙重審查之標準化劇本直接注入 System Prompt，明確界定病人年齡、主訴、伴隨症狀、陰性症狀（Pertinent negative findings）以及「從病人視角無法得知之資訊」[REF-01, p.4, p.5]。
- **少樣本對話（Few-Shot Exemplars）**：以瘧疾案例為例，Prompt 中示範當護理師問及呼吸道症狀時，模擬病人應主動確認發燒、畏寒與咳嗽，以引導模型模仿規範之臨床反應風格 [REF-01, p.5, p.8]。
- **生成參數校準（Generation Settings）**：
  - **溫度參數（Temperature）**：由預設的 0.5 調降至 0.3，藉由降低取樣隨機性提升臨床事實的穩定度與前後一致性 [REF-01, p.5, p.7]。
  - **最大長度（Max Tokens）**：設為 4000 tokens，防止長篇問答時輸出遭到強制截斷 [REF-01, p.5]。
  - **頻率與存在懲罰（Frequency & Presence Penalties）**：均設為 0，避免模型因懲罰機制而刻意逃避重複提及重要的既有症狀字詞 [REF-01, p.5]。
- **會話記憶管理（Memory Management）**：由於 LLM API 為無狀態（Stateless），系統於遊戲工作階段（Session）內保留對話歷史以維護「同一次問診」的一致性；而在每個案例結束後立即清空記憶，杜絕跨案例的資訊交叉污染 [REF-01, p.5]。
- **雲端安全過濾器調校（Safety Filter Calibration）**：通用雲端平台（如 Microsoft AI Foundry on Azure）之內容安全過濾器常對非英語系（如廣東話或中文俚語）臨床用詞產生過敏反應（如「點解你嚟睇醫生？／為什麼你來看醫生？」曾遭誤判阻斷），須在後台進行專門的領域適配微調 [REF-01, p.5, p.10]。

## 四、次世代高階技術架構：多智慧體閉環與知識圖譜（KG）
隨著系統複雜度提升，最新綜述（Jo et al., 2025）指出當前技術正邁向**「知識驅動與多智慧體混合架構（Knowledge-Driven Multi-Agent Systems）」** [REF-06, p.11–13]：

1. **動態行為自適應閉環系統（Adaptive-VP, Lee et al., 2025）**：
   - 包含四個相依模組：評估（Evaluation）→ 動態調適（Dynamic Adaptation）→ 對話生成（Dialogue Generation）→ 安全監控（Safety Monitoring）[REF-06, p.10]。
   - 系統依據學生的提問邏輯即時評分，並動態調整病患的不滿程度與合作意願，使虛擬病人的角色忠實度顯著高於靜態模型（F=4.52, P=0.043）[REF-06, p.10–11]。
2. **圖譜持續寫回機制（CureFun, Li et al., 2024）**：
   - 採 ERRG（擷取、檢索、改寫、生成）流程，當虛擬病人在問答中合理補充了原劇本未載明之細節時，系統將新生成之臨床實體**即時寫回知識圖譜（Continuous write-back）**，確保在後續長達數十輪的對話中絕不出現前後矛盾 [REF-06, p.12–13]。
3. **多智慧體協同演化（EvoPatient, Du et al., 2024）**：
   - 劃分病患 Agent 與多科醫師 Agent，透過有向無環圖（DAG）引導不同專科虛擬專家依序問診，使整體對話表現提升 10% 以上 [REF-06, p.11–12]。

## 五、模型客觀量化評估公式（Reproducible Evaluation Metrics）
為解決過往醫療評估僅依賴主觀印象之弊端，Jo 等人（2025）提出了可重現之量化數學評估指標 [REF-06, p.17]：
- **臨床表徵識別率（Recognition Accuracy, RA）**：$RA = \frac{1}{N}\sum_{i=1}^{N} C_i$（$C_i$ 代表是否正確辨識出關鍵臨床線索或生命徵象）。
- **指令與約束遵循率（Instruction-following Effective Rate, ER）**：$ER = \frac{1}{N}\sum_{i=1}^{N} F_i$（$F_i$ 代表是否嚴格遵守角色規範與不洩露隱藏資訊）。
- **加權綜合準確率（Aggregated Accuracy, AA）**：
  $$AA = \frac{\sum_{i=1}^{N} w_i A'_i RA_i ER_i}{\sum_{i=1}^{N} w_i}$$
  （式中 $w_i$ 代表各臨床情境之難度權重，$A'_i$ 為專家審定之醫學推理正確性。該指標將表徵識別、規則遵循與臨床思維加權整合為一體）[REF-06, p.17]。
